# Инструкция ежедневной подготовки черновика дайджеста

Эту инструкцию читает автоматика по будням в 9:00 (суббота и воскресенье —
без выпусков). Промпт автоматики — короткий указатель сюда; все детали
живут в этом файле, правки вносятся здесь и сразу подхватываются
запусками.

## Принцип экономии (обязательные лимиты)

- Максимум 2 веб-поиска и 3–4 проверки ссылок WebFetch на запуск.
- Не вызывать CronList/CronUpdate и другие служебные инструменты.
- Не перечитывать файлы, уже прочитанные в этом запуске.
- Черновик пишется сразу начисто; одна итерация самопроверки, без переписываний.

## Порядок работы

1. Дата — по часам хоста (YYYY-MM-DD). Если `content/news/YYYY-MM-DD.md`
   уже существует — ничего не создавать, отчитаться, что черновик ждёт
   ревью.

2. Темы — по файлу [news-topics.md](news-topics.md). Кратко: приоритет 1 —
   Go, рынок труда программистов, архитектура и построение систем,
   data-инфраструктура (PostgreSQL, Kafka; NewSQL, графовые и векторные БД,
   стриминг). Приоритет 2 — безопасность (взломы, уязвимости, разборы
   инцидентов), низкоуровневая инженерия, мега-популярное из мира ИТ,
   AI-агенты и инструменты, инженерная культура, новшества других языков,
   Ruby/Rails. Позиционные темы поверх: ущемления
   пользователей платформами, хайп ИИ против пользы, карго-культ процессов.
   Свежесть — последние ~24 часа; в понедельник — за выходные
   (суббота–воскресенье), то есть до ~72 часов: отбор строже, только
   сильнейшее.

   ИСТОЧНИКИ И РАЗНООБРАЗИЕ — обязательное правило: каждый запуск проверять
   минимум два разных типа источников (Hacker News + Хабр, или официальный
   блог + Хабр, и т.д.). Не более двух пунктов выпуска с одного сайта —
   если разнообразие не набирается, выпуск короче, а не однообразнее.
   Источники: news.ycombinator.com, habr.com/ru/top/, vc.ru, инженерные
   блоги крупных компаний (netflixtechblog.com, eng.uber.com,
   blog.cloudflare.com, discord.com/blog, shopify.engineering,
   dropbox.tech, anthropic.com/engineering), официальные блоги
   (go.dev/blog, postgresql.org, kafka.apache.org). Выбрать 3–5 пунктов;
   хотя бы один приоритета 1, если есть — один позиционный. Нумерацию
   выпусков не использовать.

3. Каждую ссылку проверить WebFetch. Битые и непроверенные не включать.
   Ссылки не выдумывать.

4. Стиль — по [news-style.md](news-style.md) (разделы «Голос», «Позиция»,
   «Кулисы остаются за кадром», «Запрещено»). Ключевое: голос автора, у
   каждого пункта позиция; короткие предложения вперемешку с глубокими;
   конкретика и числа вместо оценок; без канцелярита, сленга, восклицаний,
   ИИ-клише; кулисы за кадром; вводка — рамка дня либо её нет; заголовки
   `###` живые. Заголовок выпуска — сразу тематический, без префиксов
   («Дайджест №…», «Дайджест за …») и без нумерации.

5. Создать черновик `content/news/YYYY-MM-DD.md` с `draft: true` (Hugo
   черновики не рендерит). Файл — единственный источник: на сайт через
   `make news-publish`, в Telegram через `scripts/tg_send.sh` (генерирует
   сообщение из того же файла). Формат — по архетипу `archetypes/news.md`:
   YAML-фронтматтер (title — тематический; date `T09:00:00+03:00`;
   draft: true; description одной фразой в стиле автора; toc: false;
   build: list: local). Каждый пункт: `### Заголовок`, 2–4 предложения
   комментария с позицией, последней строкой `[Источник](https://...)` —
   ссылка последней строкой обязательна. Перекрёстные ссылки на статьи
   блога — относительные `/posts/...` внутри комментария. Объём — до 5
   пунктов, ~3000 символов.

6. Самопроверка стиля: один проход по запрещённым оборотам и сленгу;
   проверить позицию в каждом пункте. Переписать слабые места.

7. Если за сутки нечего публиковать — черновик не создавать, так и
   отчитаться.

8. Проверки без публикации: `make -C /Users/kevinglare/project/kgoryachev
   build` — должна пройти; затем из корня репозитория
   `hugo --environment development --buildDrafts --buildFuture --destination
   /tmp/news-check`, убедиться, что существует
   `/tmp/news-check/news/YYYY-MM-DD/index.html`, и `rm -rf /tmp/news-check`.
   Временных файлов в репозитории не оставлять.

9. Отчёт: заголовки пунктов; путь черновика; статус проверок; список
   черновиков `grep -l '^draft: true' content/news/*.md`; напоминание:
   после правок — `make news-publish DATE=YYYY-MM-DD`, затем
   `git add content/news && git commit && git push` и
   `scripts/tg_send.sh content/news/YYYY-MM-DD.md`.

## Ограничения

Не коммитить и не пушить, не отправлять в Telegram, не трогать файлы вне
`content/news/YYYY-MM-DD.md`, не оставлять временных файлов.
