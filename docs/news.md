# Новости: черновики и публикация

Раздел новостей один — `content/news/`. Черновик выпуска лежит прямо в нём
с `draft: true`: Hugo черновики не рендерит, поэтому пока флаг не снят,
ничего не публикуется ни локально, ни в проде. Один markdown-файл — источник
и для сайта, и для Telegram. Правки только в нём.

## Ежедневный процесс

1. В 9:00 автоматика создаёт `content/news/YYYY-MM-DD.md` с `draft: true`
   (ссылки проверены, сборка проверена). Ничего не публикует.
2. Ревью и правки — прямо в этом файле.
3. `make news-publish DATE=YYYY-MM-DD` — снимает `draft: true`,
   проверяет сборку.
4. `git add content/news && git commit -m "news: дайджест YYYY-MM-DD" && git push`
   — сайт публикуется через GitHub Actions.
5. `scripts/tg_send.sh content/news/YYYY-MM-DD.md` — TG-сообщение
   собирается из того же файла автоматически: заголовок выпуска жирным
   (префикс «Дайджест №N:» отбрасывается), заголовок каждого пункта —
   жирная кликабельная ссылка на источник, под ним полный комментарий,
   в конце — жирная ссылка «Полный выпуск» на страницу сайта. Ссылки
   на свои статьи становятся абсолютными и кликабельными. Если сообщение
   длиннее 4096 символов, скрипт сам разделит его на несколько частей
   по границам пунктов.

## Правила формата выпуска

- Файл — markdown с YAML-фронтматтером, образец: `archetypes/news.md`.
- Темы и приоритеты отбора новостей — `docs/news-topics.md`.
- `draft: true` обязателен у черновика, `build: list: local` — у любого
  выпуска (не выносит выпуски в основной RSS и на другие списки).
- Текст — в стиле автора блога, по стайлгайду `docs/news-style.md`:
  позиция и конкретика, без канцелярита и ИИ-клише. Комментарии идут
  и на сайт, и в Telegram — пиши их так, чтобы не стыдно было
  отправить подписчикам.
- http(s)-ссылка источника — последней строкой каждого пункта: именно её
  скрипт берёт в TG-версию.
- Относительные ссылки на свои статьи (`/posts/...`) в TG не попадают —
  работают только на сайте (перекрёстный трафик).
- 3–6 новостей за выпуск; пустых выпусков не делаем.

## Настройка бота (однократно)

@BotFather → `/newbot` → добавить бота администратором канала →
`cp .env.example .env` (в корне репозитория) → вписать токен и `@username`
канала. Проверка без отправки:
`scripts/tg_send.sh --dry-run content/news/YYYY-MM-DD.md`.

## Советы по ведению канала

- Рубрики: новость / исследование / чужая статья / своя статья.
- Своя статья — минимум раз в 1–2 недели: канал должен продавать блог,
  а не только раздавать чужое.
- Время постинга: будни 9:00–10:00 или 13:00–14:00 МСК — пик открытий.
- Раз в неделю — опрос или вопрос подписчикам: реакции разгоняют охват.
- Не два чужих материала подряд без своего комментария — голос автора
  это то, за чем возвращаются.
